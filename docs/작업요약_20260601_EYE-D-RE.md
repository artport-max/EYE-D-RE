## 2. 핵심 성과 — 데이터 품질 문제를 직접 잡음

이전 파인튜닝의 낮은 성능(rank-1 ~15%)의 원인은 **오염된 라벨(다른 사람이 같은 ID로 섞임)** 으로 추정됐습니다. 오늘 이걸 **육안 검수로 실제 확인하고 수정**했습니다.

병합 임계값(`reid.clustering.threshold`)을 단계적으로 조정:

| threshold | Global ID 수 | 압축률 | 검수 결과 |
| --- | --- | --- | --- |
| 0.25 (초기) | 5개 | 90.4% | ❌ 심한 over-merge (노란조끼+검은옷+남색 한 덩어리) |
| 0.15 | 16개 | 69.2% | △ 일부 개선되나 ID 013에 노랑+파랑 혼재 |
| **0.12 (확정)** | **23개** | 55.8% | ✅ 명백한 over-merge 해소 (ID 007/005/006 등 단일 인물 확인) |

→ **"한 Global ID = 한 사람"** 을 시각적으로 검증. 남은 경계 케이스(예: 남색+밝은바지 vs 남색+어두운바지)는 자동 클러스터링의 한계 영역으로, 수동 정리 또는 정책 합의 대상.

## 3. Zero-shot 평가 결과 (해석 주의)

```
mAP 19.78% | Rank-1 0.00% | Rank-5 75.00% | Rank-10 75.00%
Query 9장 / 7 ID,  Gallery 4296장
```

- **평가셋이 매우 작아(쿼리 9장/7 ID) rank-1 0%는 통계적으로 무의미.** 쿼리 1~2개 차이로 크게 출렁임.
- 의미 있는 신호는 **Rank-5/10 = 75%** → 정답 인물이 상위 5위 안에 대부분 포함됨(zero-shot 기본 OSNet 기준 양호).
- rank-1만 0%인 것은 검은 옷의 유사 인물이 많아 1순위를 닮은 distractor가 차지한 영향으로 추정.

**결론: 파이프라인·데이터 품질은 확보. 단, 성능 평가에는 데이터 양이 부족(15분=7 ID).**
